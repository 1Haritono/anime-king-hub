# Release Discipline & Versioning Rules for AniKingHub

## 1. Release Publication Discipline
- DO NOT publish GitHub Releases automatically after code changes or bug fixes.
- Always commit and push code changes to the repository as needed.
- Create and publish GitHub Releases ONLY when explicitly requested by the user.

## 2. Evidence & Verification Guidelines
- Code Edits: Full UI screenshots and visual verification are mandatory for testing UI changes.
- Release Publication: Text evidence (classification explanation, GitHub API html_url JSON response, direct asset links) is sufficient.

## 3. Versioning Classification
Determine the version number strictly based on scope:
- PATCH (x.x.N -> x.x.N+1): Small bugfixes, minor tweaks, no new features.
- MINOR (x.N.0 -> x.N+1.0): New feature, new screen, new integration, or major behavior change.
- MAJOR (N.0.0 -> N+1.0.0): Massive overhaul, multiple major features, or architectural rewrite.

Always state the version classification before publishing.

## 4. Release Asset Standard
- Anime-King-Hub-Setup-<version>.exe manually uploaded to release assets.
- Source code (zip) & (tar.gz) auto-generated by GitHub tag.

## 5. Optimized Release Workflow
- Perform tag creation, release creation, and .exe upload via a single fast API call or script.
